# Model-call profiling

Reference for operators and maintainers inspecting a terminal run in **Execution → Load model calls**.

## Capture and privacy

New Review, ReviewDraft and Resolve executions collect bounded metadata in a per-run Core collector. Execution-context-local immutable scopes carry the collector, stable stage name and agent profile. Shared transports hold no current-run fields. The physical-call wrapper sits inside the process-wide governor and below application retries, task-done guards and function invocation. Synthetic task-done responses do not count.

| Entry path | Capture boundary | Profile |
| --- | --- | --- |
| Review and draft review agent | OpenAI Responses adapter, or underlying Codex stream | Review |
| Separate finding verifier, including its format-repair request | Same provider boundary | Verifier |
| Author-commanded fix pass | Same provider boundary | Fix |
| Resolve comment triage | Same provider boundary | Triage |
| Resolve bounded edits | Same provider boundary | Fix |

Codex nonstreaming callers are adapted to one observed provider stream, not recorded twice. Streaming usage retains the last cumulative usage snapshot instead of summing repeated cumulative counts. Input, output, total, cached-input and reasoning token counts are nullable. Negative provider counts are unavailable. Response model IDs and arbitrary configured model names are not trusted: only explicitly supported provider/model identifiers are retained; others are null.

Rows contain correlation IDs, sequence, fixed stage/profile, allowlisted provider/model, UTC timing, monotonic elapsed milliseconds and closed outcome codes. Prompts, responses, source, paths, tool arguments/results, exception messages, credentials, endpoints, raw SDK representations and additional-property bags are not copied into profiles. Existing diagnostics have their own contract; profiling does not change their content.

The current OpenAI/Codex Responses adapters expose usage but no explicit provider-reported monetary cost field. Cost, currency and cost provenance therefore remain null, with `provider-not-reported` coverage. No configured pricing, estimates, subscription billing assumptions or mixed-currency totals are produced. SDK-internal retries are unobservable and marked `sdk-internal-unavailable`. Application retry wrappers now create one logical-call ID and distinct attempt IDs/numbers. Physical provider rows link to that attempt and logical call; tool rows link to the provider call that requested them. An application attempt can return a synthetic task-done guard response without any provider traffic: it is not a physical model call. A completed application attempt means transport/dispatch returned, not that a provider reported success or a finding/edit was accepted.

Every registered function is delegated without changing its declaration, arguments, cancellation, sandbox or result. Only allowlisted tool name, run/profile/stage IDs, generated correlation IDs, UTC timing, monotonic duration and closed outcome codes enter tool metadata. Unknown tool names become `unavailable`. Provider dispatch IDs are used only in a bounded transient routing map, never serialized. An immutable per-pass identity also joins streaming tool dispatch outside the SDK client iterator's execution context; concurrent passes do not share a mutable current-run field. Unmatched dispatch is labeled `missing-parent`, with a retained missing-parent count, rather than linked to the most recent call.

Governor wait is measured separately on application attempts, including cancelled/timed-out admission; no provider row is created before admission. Provider latency excludes this wait. Failed attempts finish before backoff, whose actual elapsed time is measured separately, including cancelled backoff. Logical duration includes its attempts and waits; attempt duration excludes backoff; physical-call and tool durations remain separate. Intervals can overlap and must not be added into wall-clock execution time. Retry count, jitter, maximum attempts and the no-retry-after-first-stream-update rule are unchanged. Early stream disposal remains interrupted; exceptions/cancellation keep their original propagation. Token usage belongs only to physical provider rows, never copied onto logical, attempt or tool rows.

## Storage and lifecycle

`IModelProfileStore` is the Core IO boundary. SQLite creates additive `ModelProfiles` summary rows, `ModelCalls` provider rows and `ExecutionActivities` logical/attempt/tool rows. Both detail tables have unique generated IDs and indexed `(RunId, Sequence)` paging. One shared sequence cursor pages across both tables, returning provider rows in `calls` and non-provider rows in `activities`; `nextSequence` is the last emitted sequence across both. Schema-1 T10 rows remain readable without backfilling missing correlations or activity aggregates. Existing run, finding, decision, publication and stage-diagnostic tables are not repurposed. Legacy runs are not backfilled.

After a successful gate, an incomplete marker is written without creating finding-store run history. Skipped gates write no profile marker or finding history. A process interruption leaves this marker incomplete; no missing calls are reconstructed. A reclaimed request with a finalized profile and a terminal stored run is acknowledged without rebuilding or executing its pipeline. The worker restores Completed/Failed from that stored run, even when profile details are empty, expired or incomplete. This closes the crash window between profile finalization and queue acknowledgment without replacing or merging executions. A request with only an unfinalized marker still resumes under the persisted profile identity with incomplete coverage; only newly observed calls contribute to its counts. In-memory detail is flushed only during terminal finalization, using a fresh five-second cancellation token. Call outcomes and counts represent observations, not inferred physical SDK attempts. Run and allowlisted-stage aggregates retain observed calls, separate completed/failed/cancelled/interrupted/provider-incomplete counts, observed duration, and usage summaries independently of detail rows, including calls beyond the detail cap. Logical, application-attempt and tool outcome/count/duration summaries are retained separately at run and stage levels, including interrupted and missing-parent counts. They never increment observed physical calls or usage denominators. The 10,000 maximum is shared across all four detail types, not a separate allowance for each. Activity and provider details expire together; safe summaries survive. Legacy activity counts remain unavailable rather than zero. Each token metric contains a nullable sum, reporting-call count, observed-call count and unavailable/partial/complete coverage. Partial sums are not full-run totals; reported zero remains zero, and missing usage remains null. Provider-incomplete is a fully observed provider outcome (for example, an output limit), not evidence of missing capture. Overlapping call durations are not wall-clock run time. Older run-only summary JSON remains readable with stage and usage summaries unavailable; details are never used to reconstruct them.

A reclaim-preflight read failure or shutdown cancellation is not a new execution failure: the worker preserves existing run/profile records, leaves the durable request unacknowledged, releases its PR claim, and propagates the error. A non-cancellation consumer fault cancels sibling consumers and awaits their shutdown before surfacing the original error through the hosted worker, rather than silently reducing capacity, retrying or rewriting completed history; durable queue lease recovery can retry the preflight after service recovery.

Successful profile-write failures fail the run. Failure finalization logs persistence failures without replacing the original failure, following the existing worker failure-journal behavior. Writes and cleanup are awaited; no detached writes or fallback store are used. A cleanup failure propagates to the host as a failed hosted service.

| Setting | Default | Allowed range |
| --- | --- | --- |
| `ModelProfiling:RetentionDays` | 30 | 1–3650 |
| `ModelProfiling:DetailLimit` | 10000 | 1–10000 |
| `ModelProfiling:CleanupBatchSize` | 10 profiles | 1–100 |
| `ModelProfiling:CleanupIntervalMinutes` | 60 | 1–1440 |

Options validate at startup. Retention starts at terminal completion. The collector has an independent hard maximum of 10,000 details. Cleanup runs at startup and periodically, expires a bounded batch idempotently, deletes only detail rows, and preserves profile aggregates and existing stage/decision/publication audit. Reads enforce expiration even before cleanup has deleted the rows. Duplicate terminal finalization for the same profile does not rewrite its completion, expiry or call IDs.

## Terminal reads

`GET /reviews/{runId}/model-calls?after=0&count=50` uses the existing API-key or dashboard-session authentication and status rate limit. `after` is a nonnegative sequence cursor; `count` is 1–100. Follow `nextSequence` for another page. The same-origin browser adapter accepts only this exact route/query shape. Reads do not mutate decisions or publish findings, and do not grant edit capabilities to ordinary/resolve runs.

States distinguish active/not-yet-available, skipped-not-recorded, legacy-unavailable, expired, truncated, incomplete and observed-empty profiles. Active reads never query detail storage. Failed terminal runs can expose captured completed, failed, cancelled, interrupted and provider-incomplete calls. The basic retained stage-summary table remains available after detail expiry, including reporting coverage on usage sums and separate logical/attempt/tool counts. The same endpoint and browser adapter now return correlated activity rows; their authentication, terminal-only gate and retention are unchanged. The post-run explorer exposes generated IDs, tool names, safe outcomes, governor wait and backoff, never tool content. Details are loaded explicitly after termination, not streamed live.

### Post-run explorer

In **Execution**, load model calls to inspect either a chronological timeline or a semantic table ordered chronologically or by observed duration. Type, outcome, model, tool, stage and duration filters, plus safe-metadata text search, apply **only to the current loaded page**. The browser requests at most 50 mixed provider/logical/attempt/tool records using the existing shared sequence cursor. Next/previous navigation replaces that page; it does not accumulate all details. The backend's shared 10,000-record cap and 1–100 endpoint page limit are unchanged. No filter claims server-wide or unloaded-page coverage.

Retained whole-run/stage summaries are independent of the page and survive detail expiry. Provider usage sums include only reporting physical calls, not logical/attempt parents or tools. Nullable usage and coverage remain visible; cached input is not subtracted to invent billed usage. Interval bars use observed offsets/durations within the loaded page, not summed wall-clock time. Explicit attempt numbers greater than one count as **loaded-page observed application retries**; retained summaries cannot provide a whole-run retry total, and SDK-internal retries remain unavailable. Costs shown from loaded provider rows require provider-reported provenance and are grouped separately by currency. Whole-run monetary totals remain unavailable because the retained schema has no monetary summary. Nothing is estimated from pricing or subscriptions.

Select a record for its read-only inspector, jump to a loaded parent/logical call/attempt or direct child, select its stage, or explicitly copy a correlation ID. A link whose target is not loaded stays unavailable: it may be on another page, expired, truncated or unobserved. No extra page is fetched automatically. Linked-record navigation clears page filters to reveal the target; a selected inspector snapshot remains pinned across ordinary filtering/paging until another record is selected. Expiry clears detail selection rather than retaining expired metadata. Read failures keep the last successful page with a stale-read explanation; session expiry requires sign-in, not an automatic retry.

On record buttons, Up/Down and Home/End navigate; Tab/Enter provide native alternatives. **Profiler commands & keyboard help** and Ctrl/Cmd+K expose the same read-only view/filter/focus commands. `/` focuses page search outside editable/native controls. Input, composition and open dialogs retain their native keys. Page-local scroll positions and the loaded investigation remain in circuit memory across paging and switching run sections; leaving the run retires listeners/state. No profiling payload or selection is persisted in browser storage. Real-browser focus and scroll timing remain unverified.

## Verification limits

Disposable SQLite fixtures cover additive upgrades, restart, duplicate finalization, paging and expiry without touching a user database. Collector/provider contract tests cover concurrent scopes, cancellation, privacy, cumulative streaming usage and actual OpenAI/Codex adapter boundaries. A collector-only measurement is recorded in the task verification logs; it is not a provider-latency or whole-service performance claim. App/browser startup is not authorized for this implementation; desktop/tablet/phone rendering, real focus and theme contrast remain release-verification work.
